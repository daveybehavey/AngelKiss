## Naming convention

### Storage prefix

All gallery object keys use **`studio-gallery/`** (`STUDIO_GALLERY_STORAGE_PREFIX` in `lib/admin/images.ts`). Catalog `suggested_filename` values include this prefix for clarity; at upload time the admin API may append a timestamp and random suffix.

### Recommended publish filename (catalog)

Pattern for human-chosen renames (before upload):

```text
studio-gallery/<kebab-case-descriptive-stem>.webp
```

- **Stem:** lowercase words from `display_title` or dominant subject (e.g. `fluffy-yellow-duckling-pond`).
- **Extension:** `.webp` for site delivery (source may remain `.jpg` on OneDrive).
- **No UUID in stem** unless disambiguating collisions; UUIDs stay in DB `id` from manifest.

### `sanitizeFilename()` behavior (upload path)

From `lib/admin/images.ts` — applied to the basename when building storage paths via `getStoragePathForStudioGalleryPrint()`:

1. Trim whitespace; strip directory segments (`/` and `\`).
2. Lowercase the basename.
3. Replace any character **not** in `[a-z0-9._-]` with `-`.
4. Collapse repeated hyphens; trim leading dots and leading/trailing `-`/`_`.
5. Truncate to **120 characters**; empty result becomes `upload.bin`.

**Runtime upload path** (when using the admin helper, not a manual rename):

```text
studio-gallery/<unix-ms>-<12-char-random>-<sanitized-basename>
```

Example: `studio-gallery/1734123456789-a1b2c3d4e5f6-baby-elephant-heart-frame.webp`

### iOS source filenames

OneDrive sources follow `YYYYMMDD_HHMMSSmmm_iOS.jpg` (e.g. `20260514_015904872_iOS.jpg`). These map to manifest `num` **001–159**; burst grouping uses the shared date+time prefix as in the table above.
